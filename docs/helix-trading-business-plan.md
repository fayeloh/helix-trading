# Helix Trading 商业计划书（BP）

> 版本：v0.1｜日期：2026-09-20  
> 文档性质：基于当前 MVP、产品规格、评测报告与项目资料整理的商业计划书初稿。  
> 说明：凡标注“待验证”的市场规模、客户、收入、转化率和效果数据，均不应在融资或对外材料中当作已实现事实。

## 一、执行摘要

Helix Trading 是面向跨市场个人主动交易者的“决策辅助 + 交易纪律 + 复盘”工具。它服务同时关注美股、港股和加密资产的用户，把公开市场数据、结构化研究、事件影响分析、交易前检查和事后复盘放进同一条工作流。

Helix Trading 不自动下单、不托管资金、不代客理财，也不输出买卖建议。产品的核心承诺不是“生成更多观点”，而是让每一笔交易都留下可追溯的依据：

> 基本面依据 + 事件日历 + 风险纪律检查 + 结果复盘。

当前 MVP 已完成交易台、全球市场看板、每日宏观简报、标的深度研究、账户/持仓、交易日志和事件影响复盘等产品骨架；其中 `fundamentals` 研究模块已具备 Bull / Bear 多 Agent 编排、事实校验、失败回退、执行 trace 和离线评测能力。现阶段已证明的是“可信研究工作流可以被工程化”，尚未证明多 Agent 已经带来更高投资收益或更强商业转化。

本 BP 的商业化路径是：先以个人主动交易者和投资研究重度用户为切入点，验证留存、付费和复盘行为；再向交易教育、投研社群、财富管理工具和专业研究团队扩展。第一阶段以订阅制 SaaS 为主，后续探索团队版、研究工作流 API 和白标能力。

## 二、项目与团队基础

### 2.1 项目定位

- 产品名称：Helix Trading
- 产品类别：AI-assisted trading decision-support / trading-discipline SaaS
- 首要市场：跨市场个人主动交易者
- 首要语言：简体中文，同时支持英文切换
- 首要价值：将“信息消费”转化为“有依据、可约束、可回放的决策流程”

### 2.2 发起人能力证据

现有项目资料显示，项目发起人具备测试工程、AI 评测、RAG、自动化和方法论沉淀经验：

- H1 累计提报 82 个有效 Bug，修复率 98.8%，0 个严重故障带病上线；
- 构建 221 条测试用例与 2,000 个问答对 RAG 测试集；
- 主导 46K 字 AI 评测方案、20 余份质量报告和多 Agent 测试集生成流水线；
- 具备将规则、数据集、验证器、失败处理和回放能力产品化的经历。

以上是“可信 AI 工程”能力的证据，不等同于金融牌照、投资顾问资质或已验证的投资收益能力。商业化阶段需要补齐金融合规、市场运营、用户研究和增长能力。

## 三、用户痛点与市场机会

### 3.1 目标用户的典型问题

跨市场个人主动交易者通常同时面对：

1. 信息分散：行情、财报、新闻、宏观日历和账户记录位于不同工具；
2. 研究不可追溯：AI 结论与原始事实混在一起，用户难以判断哪些是数据、哪些是推演；
3. 决策易受情绪影响：临场追涨杀跌、临时修改计划、忽略事件风险；
4. 结果无法复盘：交易结束后只记得盈亏，不知道原始论点是否成立、纪律是否被破坏；
5. 跨市场工具割裂：美股、港股、加密资产的时区、币种和数据结构不同。

### 3.2 市场机会假设

Helix Trading 关注的是“个人投资工具”与“AI 研究工具”的交叉市场。机会来自三个变化：

- 市场数据与研究工具从单一行情查看，向个性化工作流迁移；
- 大模型降低了研究摘要和解释成本，但用户对幻觉、来源和可验证性的要求同步提高；
- 投资者教育逐渐从“推荐标的”转向“建立决策过程、风险意识和复盘习惯”。

当前尚未完成 TAM/SAM/SOM 的第三方数据核验。正式融资版本应采用“目标地区 × 可触达主动交易者数量 × 年订阅价格”的自下而上模型，并用访谈、落地页和付费试点校验。

## 四、产品方案

### 4.1 产品工作流

```text
市场与事件数据
      ↓
确定性数据 grounding（来源、时间、计算字段）
      ↓
结构化研究与 AI 解读
      ↓
事实 / 推演分离 + Verifier 校验 + 安全回退
      ↓
交易前 checklist、理由、止损与仓位约束
      ↓
交易日志与事件影响复盘
      ↓
用户形成个人决策数据资产
```

### 4.2 核心模块

| 模块 | 用户价值 | 当前状态 |
|---|---|---|
| 交易台 | 汇总市场、简报和研究入口 | MVP 已有 |
| 每日宏观简报 | 将全球市场、板块、头条和日历组织成可读简报 | MVP 已有，持续增强 |
| 标的深度研究 | 基本面、财报、周期/季节性、资金流的结构化研究 | MVP 已有；fundamentals 有 Multi-Agent Harness |
| 可信度面板 | 展示事实/推演、来源、验证、Agent 状态和回退原因 | MVP 已有 |
| 账户与持仓 | 维护账户、持仓、币种和风险规则 | 已有产品骨架，真实用户数据待验证 |
| 交易纪律 | 记录理由、情绪、止损、仓位上限和 checklist | 已有产品骨架，需真实使用验证 |
| 事件影响复盘 | 对比预测方向、实际方向、D+1/D+5/D+20 与组合影响 | 已有产品骨架，数据闭环待验证 |

### 4.3 产品边界与合规原则

- 不自动执行交易，不接触用户资金；
- 不提供个性化买卖建议或收益承诺；
- 对 AI 输出区分事实、推演、置信度和来源；
- 缺失数据明确显示“暂无数据”，不以模型生成内容填空；
- 研究失败时安全回退或拒绝交付，而不是编造报告；
- 页面固定显示“仅供分析辅助，不构成投资建议”。

## 五、核心竞争力与壁垒

### 5.1 差异化定位

多数行情工具优化“看得更快”，多数 AI 投资工具优化“说得更多”。Helix Trading 优化的是“决策过程是否可验证、可约束、可复盘”。

### 5.2 当前技术壁垒

1. 确定性数据 grounding：由代码处理数字与来源，模型负责解释；
2. 事实/推演分离：用户能区分原始事实与模型判断；
3. 程序化 Verifier：对数字和日期事实做 grounding 校验，失败时重试或拒绝；
4. Multi-Agent 可观测性：保留 Bull/Bear、Synthesizer、Verifier 状态、耗时和 fallback 原因；
5. 可复现评测：使用冻结输入、Golden fixtures 和单模型对照，支持离线重算；
6. 决策数据闭环：交易前计划、执行记录、事件结果和复盘逐步形成用户自己的数据资产。

### 5.3 仍需验证的壁垒

当前 AAPL/CRWV 小样本评测显示，Multi-Agent 没有被证明优于单模型，且延迟明显更高。后续必须扩大数据集、增加语义级评测、来源 attribution、成本与延迟监控，才能将“可信研究层”升级为可量化的长期壁垒。

## 六、目标客户与使用场景

### 6.1 第一阶段客户画像

- 已经交易美股、港股或加密资产中的至少两类；
- 有固定研究习惯，但工具分散；
- 愿意记录交易理由并接受交易前检查；
- 关注风险管理和复盘，而不是只寻找短线信号；
- 能接受订阅制软件，愿意为节省研究时间和提高流程纪律付费。

### 6.2 优先场景

1. 开盘前：查看全球市场、宏观事件和持仓相关风险；
2. 研究阶段：输入代码，查看事实、来源、推演和可信度；
3. 下单前：填写交易理由、计划止损、仓位上限并运行 checklist；
4. 交易后：记录执行偏差、情绪和论点是否成立；
5. 事件后：复盘预测方向与 D+1/D+5/D+20 真实反应。

## 七、商业模式

### 7.1 建议的分层订阅

以下为待通过定价实验验证的初始假设，不是已承诺价格：

| 版本 | 目标用户 | 建议能力 | 定价假设 |
|---|---|---|---:|
| Free | 体验用户 | 有限市场看板、每日简报、少量研究次数 | 0 |
| Pro | 高频个人主动交易者 | 全量研究、持仓简报、交易纪律、复盘和更高额度 | ¥69–129/月 |
| Deep Research | 研究重度用户 | 更高 AI 额度、历史研究、批量研究、导出和高级评测 | ¥199–399/月 |
| Team / API | 投资教育、社群、研究团队 | 多用户工作区、模板、审计日志、API/白标 | 定制报价 |

### 7.2 收入来源

- 个人订阅收入：首要收入来源；
- 团队席位收入：面向投资教育、研究社群和小型研究团队；
- API / 白标收入：在数据、合规和稳定性成熟后探索；
- 不以广告、荐股返佣或交易导流作为核心商业模式，以降低利益冲突。

### 7.3 单位经济模型（待验证）

正式模型至少应追踪：ARPU、毛利率、AI 单用户成本、月活到付费转化率、月流失率、CAC、LTV、回本周期。早期不宜先承诺收入规模，建议先用 20–30 位种子用户验证：

- 是否每周至少使用 3 次；
- 是否持续完成交易前 checklist；
- 是否在交易后 7 天内完成复盘；
- 是否愿意从免费转为付费；
- AI 成本是否低于订阅收入的 25%–35%。

## 八、获客与增长策略

### 阶段 1：种子用户验证（0–3 个月）

- 邀请 20–30 名跨市场主动交易者进行封闭测试；
- 通过交易复盘、研究效率和纪律执行三个维度做结构化访谈；
- 建立落地页、候补名单和 14 天试用；
- 只宣传可验证的产品能力，不宣传收益改善。

### 阶段 2：内容与社群增长（3–9 个月）

- 输出“事实与推演如何分离”“交易复盘模板”“跨市场事件日历”等内容；
- 与投资教育社群、交易工具评测者和研究型创作者合作；
- 通过可分享的研究报告、复盘卡片和个人方法模板形成自然传播；
- 用匿名化聚合数据展示流程指标，如复盘完成率，而不是展示收益排名。

### 阶段 3：团队与 API（9–18 个月）

- 面向投教机构和研究团队提供共享模板、权限和审计日志；
- 将研究 grounding、验证器和复盘事件接口化；
- 探索白标部署，但保留合规、数据来源和模型输出边界。

## 九、竞争格局

| 类型 | 优势 | 局限 | Helix Trading 的切入点 |
|---|---|---|---|
| 券商/行情终端 | 行情和交易执行强 | 研究、纪律和复盘割裂；跨平台体验有限 | 不做执行，专注决策流程闭环 |
| 财经资讯/研究平台 | 内容和数据丰富 | 用户仍需自行整理判断与记录 | 将信息转成结构化研究与行动前检查 |
| 通用 AI 聊天工具 | 交互灵活、成本低 | 来源、事实核验、持仓和复盘不成体系 | grounding、Verifier、trace 和领域工作流 |
| 交易日志/复盘工具 | 记录能力强 | 缺少实时研究和事件影响分析 | 将研究、执行约束和复盘连起来 |
| AI 投资信号产品 | 结果导向、营销容易 | 合规和幻觉风险高，可能诱导交易 | 明确不荐股、不自动下单，以过程可信为核心 |

## 十、技术与运营路线图

### 0–3 个月：验证可用性与付费意愿

- 扩充 Golden Dataset 和语义级 Judge；
- 完善来源 attribution、成本、延迟和模型质量监控；
- 补齐账户、持仓、交易日志和复盘的真实端到端闭环；
- 完成种子用户访谈、可用性测试和首轮定价实验；
- 建立内容、反馈和问题分级机制。

### 3–6 个月：形成可交付 Pro 版本

- 研究、宏观简报和交易纪律达到稳定可用；
- 支持更多数据源降级和可解释错误状态；
- 提供导出、历史搜索、研究收藏和复盘统计；
- 达到首批付费用户和稳定周留存目标；
- 完成隐私、数据保留、免责声明和服务条款审查。

### 6–12 个月：验证团队化商业化

- 推出团队工作区、模板、权限和审计日志；
- 评估 earnings 与宏观多阶段 Agent 流水线，前提是评测证明投入产出合理；
- 探索研究 API 和白标能力；
- 建立可观测的单位经济模型与增长漏斗。

## 十一、关键指标（建议）

### 产品指标

- 激活率：注册后完成首次研究或首次 checklist 的比例；
- 周留存 / 月留存；
- 每周研究次数与研究完成率；
- 交易前 checklist 完成率；
- 交易后 7 天内复盘率；
- 研究报告来源覆盖率、事实校验通过率和安全拒绝率；
- 平均响应延迟、fallback 率和 AI 单次成本。

### 商业指标

- 试用到付费转化率；
- ARPU、MRR、月流失率；
- CAC、LTV 和回本周期；
- Pro 用户的 AI 成本率；
- 团队客户席位数和净收入留存。

### 不能直接使用的指标

在没有真实用户和可复现实验前，不应宣称“提高收益率”“战胜市场”“降低亏损”或“显著提高胜率”。事件影响复盘可以记录预测命中率，但命中率不等于投资收益，也不构成投资建议。

## 十二、融资与资源需求（建议写法）

当前更适合采用“验证型融资/资源申请”，而非基于未经验证的收入预测提出大额融资承诺。建议资金或资源优先投入：

1. 产品与数据工程：研究可靠性、数据源稳定性、成本控制；
2. 用户研究与增长：种子用户招募、访谈、内容和试用漏斗；
3. 合规与安全：隐私、数据处理、免责声明、服务条款和模型风险审查；
4. 团队补齐：金融产品、用户增长和商业化运营能力。

正式融资版需要补充：融资金额、出让比例或资金用途比例、18 个月现金 runway、月度预算、人员计划、里程碑和下一轮融资条件。上述数字目前尚未在项目资料中形成可靠依据，因此本版不虚构填写。

## 十三、主要风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 合规风险 | 用户将研究解读为荐股或投资顾问服务 | 明确产品边界；法务审查；不自动下单、不承诺收益 |
| 数据风险 | 免费数据源限流、延迟或字段缺失 | 多源、缓存、降级、来源和更新时间展示 |
| 模型风险 | 幻觉、推演冒充事实、Agent 成本和延迟高 | grounding、Verifier、拒绝交付、离线评测和成本监控 |
| 用户留存风险 | 用户只看行情，不愿记录和复盘 | 降低 checklist 门槛；用事件提醒、模板和复盘统计形成习惯 |
| 商业化风险 | 用户认为通用 AI 已足够 | 证明工作流、可信度和复盘数据资产的独特价值 |
| 市场风险 | 交易活跃度和用户付费意愿随行情周期变化 | 以纪律、研究和复盘为长期价值，不依赖牛市收益叙事 |
| 团队风险 | 产品、金融和增长能力集中在少数人 | 优先补齐合规、用户研究和商业化合作者 |

## 十四、投资人/评审人应记住的三句话

1. Helix Trading 不是另一个“告诉你买什么”的 AI，而是把交易决策变成可验证、可约束、可复盘的过程。
2. 当前 MVP 已证明可信研究工作流的工程可行性，但尚未用大样本证明投资收益或多 Agent 优势；项目选择把边界和不足公开出来。
3. 下一阶段的核心任务不是继续堆功能，而是用真实用户验证三个问题：用户是否持续使用、是否愿意付费、是否愿意把交易纪律和复盘迁移到 Helix Trading。
